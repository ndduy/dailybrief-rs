# Spec: R0 — the Rust service, built in full

Milestone spec derived from `SPEC.md` (v4). `SPEC.md` stays the source of truth for settled decisions and contracts; this file turns it into the R0 PRD that the toolkit loop (`/plan` → `/build` → `/test` → `/review` → `/ship`) works from. Contracts are referenced by section, not copied. Where this file deviates from `SPEC.md` it says so in §11 and each deviation gets an ADR at `/ship`.

Status: **approved 2026-09-17.** Nothing is built yet (`src/main.rs` is hello-world).

---

## 1. Objective

Ship a Rust service that builds a 30-item digest every morning through the Editor agent on the Max subscription, serves it on the phone behind Cloudflare Access, and does so from this repo alone.

**User:** Duy, sole user. Reads the digest each morning on a phone, taps through to sources; occasionally presses Refresh; reads a failed run's transcript when a morning is empty.

**Two goals of equal weight** (`SPEC.md` preamble): a digest Duy reads, and practising agent engineering — now in Rust. R0 practises tool-surface design, prompt-as-contract and headless harness configuration on the agent side; ownership and borrowing in a real service, `serde`/`schemars` contract types, `tokio` process and blocking boundaries, and `thiserror` error design on the Rust side.

**Done for R0** (`SPEC.md` §8, restated as testable conditions in §9):
- the full `cargo test` suite proves the nine tools, every contract violation, the adapter against a fake `claude`, the env scrub, the bind guard, the byte-stable prompt and the schema-drift check;
- the container serves on `127.0.0.1:8788`, and three consecutive scheduled 06:30 runs publish 24 + 6 on subscription usage;
- the digest is read on the phone through the existing tunnel and Access app; source clicks land in `reads`;
- a real transcript passes the egress scan; rollback is one documented command.

**Out of scope for R0** (later milestones): parsed per-turn trajectory pages (M2), ratings and Curator (M3), Codex adapter (M4), `/stats` `/feeds` `/topics` and the runbook (M5), own loop (M6), evals (M7), routines (M8), and the `seed` command (deferred, §11). R0 still stores the raw `stream-json` transcript and every line in `run_events` so M2 parses without re-running anything.

Build order: `config-db` → `core-ingest` → `core-select` → `mcp-editor` → `editor-contract` → `harness-claude` → `web-read` → `ops`. No cycles. Interfaces live in the provider module: tool schemas in `mcp-editor`, the digest output schema in `editor-contract`, the `Harness` seam in `harness-claude`. `ops` lands its Docker task before the first `/ship` (`CLAUDE.md` conventions); until then host `cargo` 1.98.1 is acceptable for slices.

**Decided at `/plan`, before any code (five ADRs, `docs/adr/0001`–`0005`):** harness dispatch (enum vs `dyn`), the `Db` closure boundary and connection pragmas, the scheduler crate (`tokio-cron-scheduler` vs a `croner` loop), the coverage mechanism (per-module scoping vs one floor), and `fastembed` feature pinning (rustls). The plan links each task to the ADR it depends on. Everything else from the Rust review (char-based caps, little-endian chunked vectors, `nix` for SIGTERM, stderr-only logs in `mcp`, concurrent stderr drain, rmcp error mapping, canonical-URL and hash rules, item id format, percentile formula, schema-drift compare, build profiles, test layout) becomes an acceptance criterion phrased as a named test on the task that touches it.

## 4. Commands

Everything runs inside the `test` container once `ops` lands; until then the same commands run on the host.

```
bin/dc cargo <cmd>                 # any cargo command inside the test container
bin/check fast                     # cargo build --all-targets (-D warnings) + clippy -D warnings + fmt --check   ≤ 60 s warm
bin/check task                     # fast + cargo test + gen-schemas --check                                       ≤ 4 min
bin/check full                     # task + cargo llvm-cov (floors) + cargo deny check + gitleaks detect --redact

docker compose build                          # dev + runtime targets
docker compose --profile dev up               # cargo watch -x 'run -- serve' on 127.0.0.1:8788
docker compose --profile app up -d            # production service

dailybrief serve                              # web + scheduler
dailybrief run [--harness claude-code] [--kind manual|scheduled] [--attempts 1|2] [--no-verify]
               [--prompt <file>] [--schema <file>] [--message <text>]
dailybrief fetch                              # ingest only
dailybrief mcp                                # stdio MCP server (spawned by claude via mcp.json)
dailybrief migrate                            # apply pending migrations (serve/run do this too)
dailybrief reembed                            # re-embed every item and topic (first deployment)
dailybrief scan-transcript <path>             # egress scan; non-zero exit on findings
cargo run --bin gen-schemas -- [--check]      # regenerate / verify schemas/digest.json
```

Smoke run (the only test that spends subscription usage, once per task at most):
`dailybrief run --no-verify --attempts 1 --prompt prompts/smoke.md --schema schemas/smoke.json --message "Call get_briefing, then answer with the date."`

## 6. Code style

Edition 2024. `#![forbid(unsafe_code)]`. No `unwrap`/`expect` outside `#[cfg(test)]` and `main.rs`. `thiserror` enums per module; `anyhow` only in `main`. Every boundary (config file, env, tool input, tool output, harness event, agent final message) is a `serde` type; wire names are `camelCase` via `rename_all`. All SQL in `db::repo`, taking `&Connection`; `Db::call` owns `spawn_blocking`. Blocking crates (`rusqlite`, `fastembed`, `dom_smoothie`) never run on the async runtime directly. Text caps are counted in `chars()`, words in `split_whitespace()`. Logs go to stderr. Tool errors are typed and rendered to one imperative sentence the agent can act on.

```rust
// src/mcp/tools/read_item.rs
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

use crate::core::staging::{self, Staging};
use crate::mcp::error::ToolError;

#[derive(Debug, Deserialize, JsonSchema)]
#[serde(rename_all = "camelCase", deny_unknown_fields)]
pub struct ReadItemInput {
    /// Item id from list_candidates or search_items.
    pub id: String,
}

#[derive(Debug, Serialize, JsonSchema)]
#[serde(rename_all = "camelCase")]
pub struct ReadItemOutput {
    pub id: String,
    pub title: String,
    pub source: String,
    pub text: String,
    pub word_count: u32,
    pub truncated: bool,
}

/// Reads an item within the run's read cap and records the read.
/// Contract violations come back as `ToolError`, which the server renders as an
/// `isError` result — never as a protocol error.
pub async fn read_item(staging: &Staging, input: ReadItemInput) -> Result<ReadItemOutput, ToolError> {
    let read = staging.read(&input.id).await?; // Db::call inside; ToolError::{UnknownItem, ReadCap}
    Ok(ReadItemOutput {
        id: read.id,
        title: read.title,
        source: read.source,
        text: read.text,          // already capped by chars(), not bytes
        word_count: read.word_count,
        truncated: read.truncated,
    })
}
```

Conventions: modules `snake_case`, types `CamelCase`, one file per tool, one `ToolError` variant per contract violation with its message snapshot-tested by `insta`. Prompt text lives in `prompts/`, never in Rust strings.

## 7. Testing strategy

Every task ships with tests that fail before and pass after. Real model, real network and real `claude` are opt-in or manual.

| Level | Concern | How |
|---|---|---|
| Unit | config + `TryFrom` validation | valid and invalid TOML/env samples; unknown keys rejected |
| Unit | vectors, hashes, canonical URLs, caps, percentile | table tests incl. non-ASCII text and odd-length blobs |
| Unit | dedupe / profile / candidates / staging / digest | in-memory SQLite migrated with the real ledger; fake `Embedder` (hash → unit vector) |
| Unit | `db::repo` | every function against in-memory SQLite; ledger applied twice is a no-op |
| Integration | MCP tools | rmcp client over an in-process duplex against the real server; asserts the nine names, input field names, caps, every `select` / `publish_digest` violation (`SPEC.md` §4), the 45-read cap, the third-rejection `fatal` flag, `isError` mapping, stdout purity of `mcp` |
| Integration | ingest | `wiremock` feeds and pages; 304 handling; body cap; redirect limit; fixtures under `tests/fixtures/` |
| Integration | web | `axum` `oneshot` requests: `/r/{id}` writes `reads` and 302s; failed-run state renders; `POST /run` 202/409/403/429/503; 401 without a valid Access assertion; bind guard |
| Integration | harness adapter + runner | `tests/fake-claude/claude` on `PATH` replays transcripts: success, `error_max_turns`, hang → wall-clock kill (SIGTERM then SIGKILL), non-zero exit, no `result` line, chatty stderr; asserts `runs` rows, retry-once, transcript file, `run_events`, env scrub, argv snapshot |
| Integration | egress scan | `scan-transcript` on a fixture with a planted vault path / topic description / foreign `read_item` text |
| Integration | compose | `tests/it/compose.rs` parses `compose.yaml`: `127.0.0.1:8788` only, no `ANTHROPIC_*` anywhere |
| Slow (opt-in) | real embeddings | `EMBED_REAL=1 cargo test embed_real`; loads BGE-small from `data/models/`; not in CI |
| Manual gate | real `claude -p` smoke run | inside the runtime container; result read in the log and on the page; the only test that spends usage |
| All | execution environment | every command via `bin/dc` once `ops` lands; CI builds the same image and runs `bin/check full` |

Coverage floors and the check budget are in `CONSTRAINTS.md`. No test may be skipped or deleted to get green.

## 9. Success criteria (R0 gate, testable)

1. `bin/check full` passes on `main` at the ship commit, inside the `test` container.
2. The MCP integration tests prove all nine tools by name and field, every violation in `SPEC.md` §4, the 45-read cap, the third-rejection `fatal` flag, and that `mcp`'s stdout carries only JSON-RPC frames.
3. The adapter and runner tests prove success, `error_max_turns`, wall-clock kill, non-zero exit, no-`result`, chatty-stderr survival and retry-once against the fake `claude`, with correct `runs` rows, `run_events` and transcript files; the argv snapshot matches `SPEC.md` §3 flag for flag.
4. `cargo run --bin gen-schemas -- --check` is green and `schemas/digest.json` is unchanged from the committed input.
5. `dailybrief migrate` on a copy of the existing `brief.db` applies nothing and the copy is byte-identical afterwards.
6. One real smoke run inside the runtime container ends with a transcript whose `system/init` lists `mcp_servers: [{ name: "dailybrief" }]` and only `WebSearch` plus the nine `mcp__dailybrief__*` tools.
7. One real `dailybrief run` ends with `runs.status = success`, a `digests` row with 24 + 6 items, and `scan-transcript` clean. The `result` line is attached to the ship commit.
8. Three consecutive scheduled 06:30 runs succeed; a failure restarts the count. Dates recorded in the ship ADR.
9. Duy opens `https://dailybrief.hundredclouds.com/` on the phone after Access OTP and taps one item; the `reads` row exists.
10. The service environment, `.env`, compose, Dockerfile and unit file contain no `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`; the env-scrub test passes; `docker history` of the image shows no secret.
11. Rollback is one documented command that has been executed once during the R0 window.

## 10. Boundaries

**Always**
- `bin/check fast` after every edit, `bin/check task` before every commit; one commit per task, tests included. Never use host cargo for a gate once the image exists.
- Validate every input at the boundary with `serde` + `TryFrom`; unknown keys are errors.
- Keep tool results compact JSON; keep `prompts/editor.md` byte-stable; dynamic context goes through `get_briefing`.
- Spawn `claude` with the exact `SPEC.md` §3 flags and a scrubbed environment; store every raw transcript line before parsing.
- Compute embeddings locally; bind `127.0.0.1` only; write the ADR before `/ship` for each decision in §11.
- Read the docs.rs page of the resolved crate version before writing against it; verify harness flags against `claude --help` before relying on them.

**Ask first**
- Adding a crate not listed in §3; changing a `SPEC.md` §1 decision; changing a tool's name or schema after `mcp-editor` ships.
- Any migration appended to the ledger; any deletion of data.
- Running the real `claude -p` smoke test more than once per task.
- Cloudflare dashboard changes and anything needing `sudo` (Duy runs those).
- Editing `SPEC.md`.

**Never**
- Put `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` in `.env`, `config/`, `compose.yaml`, the Dockerfile, a shell profile, or the spawn environment; never pass `--bare`; never bake the OAuth token into the image; never commit `.env`.
- Read vault content at runtime; send topic descriptions, vault paths, or anything except public article text and topic names to a model or web API.
- Add a deterministic fallback for a failed run; substitute a digest silently.
- Let any tool other than `publish_digest` write a digest; let any R0 tool write `topics` or `sources.weight`.
- Write `unsafe`; `unwrap` outside tests and `main`; SQL outside `db::repo`; logs to stdout in `mcp`.
- Commit `data/`, transcripts, or model files; skip or delete a failing test; weaken `CONSTRAINTS.md`.

## 11. Assumptions and deviations from SPEC.md

1. **`seed` is deferred out of R0** (approved 2026-09-17). `config/topics.toml` is committed and never re-seeded; the module has no consumer in R0. `SPEC.md` §7b lists it "any time after `config-db`"; it moves to M3 alongside the Curator, which is the next thing to touch topics. → ADR.
2. **Five architecture choices are made at `/plan`, not here** (harness dispatch, `Db` boundary, scheduler, coverage mechanism, `fastembed` features). `SPEC.md` names both options for the scheduler and leaves dispatch to an ADR; this file keeps that.
3. **Rust-specific rules live in task acceptance criteria**, phrased as named tests, not in `SPEC.md` prose (decided 2026-09-17 via idea-refine).
4. **Claude Code in the image**: prefer the native installer at an exact version; fall back to `node:26-bookworm-slim` + npm if the native build does not honour `CLAUDE_CODE_OAUTH_TOKEN` and `--restricted` identically. Verified at the `ops` task, recorded in the Docker ADR. The host runs 2.1.274 today.
5. **gitleaks will be installed** on the box (approved); the gate is real from the first `/ship`.
6. **`cargo deny` licence allowlist**: MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, Unicode-3.0, MPL-2.0. Anything else is a `deny.toml` exception with a reason.
7. **Model alias `opus`** from `config/config.toml`, overridable there.
8. **The tunnel hostname and Access app already exist**; no dashboard work is expected in R0. `CF_ACCESS_AUD` and `CF_ACCESS_TEAM` come from the existing Access app.
9. **The existing `brief.db`** is copied into the `dailybrief-data` volume at first deployment; `migrate` is a no-op on it and `reembed` rewrites every vector once.
