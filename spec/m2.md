# Spec: M2 — trajectories on the page, and the R0 review backlog

Milestone spec derived from `SPEC.md` §8 (M2 row) and the post-R0 backlog in `tasks/todo.md`. `SPEC.md` stays the source of truth; `spec/r0.md` stays the reference for everything R0 settled (commands, code style, boundaries) and is referenced, not copied. Deviations from `SPEC.md` are listed in §11 and each gets an ADR at `/ship`.

Status: **draft 2026-09-21, awaiting approval.** R0 shipped 2026-09-21 (`docs/ship/r0.md`); its last live criterion (three consecutive 06:30 runs) closes on 2026-09-24. M2 may be planned before that and built after it.

---

## 1. Objective

Make every morning's run readable as a story, and retire the review findings that R0 shipped with.

**User:** Duy, sole user. Opens the run page when a morning looks odd ("why only 24 items", "why did it take 14 minutes", "did it retry"), and otherwise never thinks about it. Also the maintainer who wants the box to stay healthy without attention: disk bounded, error text safe to display, caps enforced the way the spec says.

**Two goals of equal weight** (`SPEC.md` preamble). Agent side: trajectory capture and *reading* trajectories, the skill M7's evals are built on. Rust side: internally tagged `serde` enums with unknown-variant fallbacks over a stream that changes underneath us, and streaming line parsing under backpressure.

**Done for M2** (`SPEC.md` §8 gate, restated as testable conditions in §9):
- every turn of a run is visible on `/runs/{id}` with its tool, argument summary, result size, elapsed time and tokens; the caps a run consumed are shown against their limits; the retry chain is shown;
- a deliberately failed run (`--max-turns 5`) renders correctly on `/` and on its run page;
- transcripts and events older than 60 days are pruned daily; the run list is not;
- every open item of the R0 `/ship` review has a named test and is closed or explicitly deferred with a reason.

**Out of scope for M2:** ratings and the Curator (M3), editor-notes history (M3), the Codex adapter (M4), `/stats` `/feeds` `/topics` and the systemd unit (M5), evals over the trajectories this milestone makes readable (M7).

## 2. Capability map (approved 2026-09-21)

|---|---|---|
| `trajectory` | Typed `stream-json` model: an internally tagged `Event` enum (`system` with `init` / `thinking_tokens` / other subtypes, `assistant`, `user`, `tool_progress`, `rate_limit_event`, `result`, and an `Unknown` fallback that keeps the raw value) replacing today's `Other { raw }`; bounded-channel line delivery from the adapter to the writer that never drops a line (the adapter waits, the child blocks on its pipe); pure folding of `run_events` into `Turn`s (index, timestamp, tool, argument summary, result chars, seconds since the previous turn, input/output/cache tokens), a `CapsUsed` summary (reads, selects, web searches, turns, wall clock, each against its configured cap) and a `RetryChain` (attempt 1 outcome → attempt 2 outcome) | R0 `harness-claude` |

| `ops-m2` | Vendored `install.sh` with a recorded sha256, `COPY`ed into the image; `curl` and `zstd` removed from the runtime image after the installer step; `deny.toml` licence list aligned with `CONSTRAINTS.md`; unused `harness.mcp_command` config key dropped; R0 image tagged `dailybrief-rs:r0` as the rollback target; runbook entries for the token renewal date and the 2026-12-17 advisory expiries | all above |

Build order: `trajectory` → `run-view` → `harness-hardening` → `retention` → `web-hardening` → `core-hardening` → `ops-m2`. No cycles. The first two carry the gate; the hardening modules are independent of each other and ordered by the risk they retire. Interfaces live in the provider: the `Event` enum and the folding functions in `trajectory`; the prune policy in `retention`.

## 3. Tech stack

No new crates. Everything M2 needs is in `Cargo.lock` at the versions `spec/r0.md` §3 verified: `serde`/`serde_json` (tagged enums), `tokio` (bounded `mpsc`), `chrono`/`chrono-tz` (turn timing, the daily job), `maud` (views), `croner` (the prune schedule, same loop as ADR 0003), `insta` (turn-table snapshots), `wiremock` (JWKS throttle). Adding a crate is an ask-first item (§10).

Claude Code stays pinned at 2.1.274 in the image. The event shapes in §8 were observed on that version; a version bump re-runs the observation and the `Unknown` fallback carries anything new until the model catches up.

## 6. Code style

`spec/r0.md` §6 applies unchanged. M2-specific:

```rust
/// One stdout line of `claude -p --output-format stream-json`. Unknown `type`s are kept,
/// never dropped: the page shows them as "unknown", the fold ignores them.
#[derive(Debug, Clone, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum Event {
    System(SystemEvent),          // subtype: init | thinking_tokens | other (kept as a string)
    Assistant { message: Message, #[serde(default)] timestamp: Option<String> },
    User { message: Message, #[serde(default)] timestamp: Option<String> },
    ToolProgress(Value),
    RateLimitEvent(Value),
    Result(ResultEvent),
    #[serde(other)]
    Unknown,
}
```

- Folding functions take `&[RunEvent]` and the caps, return plain structs, and never touch the database; the route does one `Db::call` and one render.
- A turn's tokens come from that assistant message's `usage`; the run's totals are read from the `result` line, and a test asserts the folded sum reconciles (turns, output tokens) within the `result`'s own accounting.
- The run page for a 120-turn run stays under 64 KiB; the digest page keeps its 15 KiB cap.
- Redaction is one function in `harness::claude_code` with its own tests; the stored value is what the page shows, so nothing is redacted at render time.
- `prune` deletes in this order: the transcript file, the run directory, the `run_events` rows; a failure in step 1 leaves the rows, so the page keeps showing what the file no longer has. Never the `runs` row.

## 7. Testing strategy

`spec/r0.md` §7 applies. M2 adds these rows:

| Level | Concern | How |
|---|---|---|
| Unit | `Event` parsing | every line of the real fixture parses to a non-`Unknown` variant; a line with a new `type` parses to `Unknown`; a line with a new `system` subtype keeps the subtype string |
| Unit | folding | turns, caps, retry chain from hand-written event lists; a `user` line without a matching `tool_use` id does not panic |
| Integration | `trajectory` on the real fixture | turn count = `result.num_turns`; output tokens sum = `result.usage.output_tokens`; wall = `result.duration_ms` ± 1 s; reads 33, selects 31, searches 8 |
| Integration | web | `/runs/{id}` renders the caps bar, retry chain and every turn (insta snapshot of the table for the fixture); the failed state on `/d/{date}` shows the bar; size cap |
| Integration | adapter backpressure | the fake emits 10 000 lines faster than the writer consumes; every line lands in the file and `run_events`, in order |
| Integration | retention | a temp data dir with three runs (30, 61, 400 days old): `prune` deletes two directories and their events, keeps all three `runs` rows; `--dry-run` deletes nothing; the daily job fires once after the morning run with the injected clock |
| Integration | hardening | one named test per backlog item (§9 #4 lists them) |
| Manual gate | forced failure | one real `run --attempts 1 --max-turns 5`; page checked on the phone; transcript captured as the `max-turns-5` fixture |

Coverage floors and the check budget stay as `CONSTRAINTS.md` says; the measured numbers must not fall below R0's (95.4 % core, 81.0 % rest).

## 9. Success criteria (M2 gate, testable)

1. **Every turn visible.** `/runs/{id}` for the real fixture lists one row per assistant turn with tool, argument summary, result size, seconds since the previous turn and tokens; the header shows reads / selects / web searches / turns / wall clock against their caps and the attempt chain. Snapshot-tested; total turns and output tokens reconcile with the `result` line.
2. **Forced failure renders correctly.** One real `run --attempts 1 --max-turns 5`: `runs.status = failed` with `error_max_turns`; `/` shows "No digest — run failed" with the caps bar reading `turns 5/5` and a link to the run page; the run page shows the five turns; `scan-transcript` clean. The transcript becomes the `max-turns-5` fixture.
3. **Retention works and is bounded.** The retention tests in §7 pass; after the first live prune the box's `/data/runs` holds only the last 60 days; `runs` still lists every run since 2026-09-16.
4. **The R0 review backlog is closed by name.** Each of these tests exists and passes: `run_hang_ignoring_sigterm_is_sigkilled_after_grace`, `killed_runs_keep_their_transcript_and_events`, `stderr_tail_is_redacted_before_storage`, `scan_transcript_checks_runs_error`, `invalid_utf8_line_does_not_end_the_run`, `publish_after_fatal_is_refused`, `run_status_reflects_a_scheduled_run`, `jwks_forced_refetch_is_throttled`, `manual_run_cap_counts_runs_not_attempts`, `auth_rejects_hs256_token_with_rs_key_material`, `find_duplicate_loads_vectors_once_per_batch`, `title_hash_dedupe_is_scoped_to_the_window`, `ingest_skips_near_duplicate_by_cosine`, `fetch_sources_runs_once_under_concurrent_calls`, `prune_keeps_runs_rows_and_recent_runs`, `prune_dry_run_deletes_nothing`, `daily_prune_fires_after_the_morning_run`, `lines_are_never_dropped_under_backpressure`. The `readability` decision is an ADR with the measurement in it, whichever way it goes.
5. **Image and docs.** `docker history` shows the vendored installer and no `curl`/`zstd` in the final layers; `deny.toml` and `CONSTRAINTS.md` list the same licences; `config.toml` has no `mcp_command`; `docs/runbook.md` exists with the renewal date and the advisory expiries; `dailybrief-rs:r0` exists on the box and is the documented rollback.
6. **Gates.** `bin/check full` green in the container at the ship commit; CI green; coverage not below R0's numbers. M2 deploys only between mornings, and a failed morning after a deploy rolls back to `dailybrief-rs:r0` before anything else is tried.

## 10. Boundaries

`spec/r0.md` §10 applies in full. M2 adds:

**Always**
- Keep every raw line: the typed model is a view over `run_events`, never a filter on what is stored.
- Deploy M2 changes between mornings (after 07:00, before 23:00 local) so a scheduled run never lands on a half-deployed service.

**Ask first**
- The one `--max-turns 5` gate run (pre-approved once, 2026-09-21); any further real run.
- The first live `prune` on the box (pre-approved at 60 days; run `--dry-run` first and show the list).
- Changing a cap value in `config.toml`.

**Never**
- Delete a `runs` row, a `digests` row, a `reads` row, or anything under `data/` other than what `prune` names.
- Change `prompts/editor.md` or `schemas/digest.json` (M2 is read-only with respect to the Editor's contract; `--max-turns` is a harness argument).
- Render a stored value without the redaction having happened at write time.
- Let the run page fetch anything client-side; it is server-rendered like every other page.

## 11. Assumptions and deviations from SPEC.md

1. **`/runs/{id}` supplements `/runs/{id}/log`** rather than replacing it (approved 2026-09-21). `SPEC.md` §8 names only `/runs/{id}`. → ADR 0012 (trajectory model and the two views).
2. **Retention at 60 days** is new; `SPEC.md` has no retention policy. → ADR 0013.
3. **`--max-turns` as a CLI override** of `harness.claude-code.max_turns`; `SPEC.md` §3 reads the cap from config only. Needed for the gate; documented as manual-only.
4. **The review backlog is folded into M2** (approved 2026-09-21); `SPEC.md`'s M2 row lists only the trajectory work.
5. **`readability` keep-or-drop** is decided by a measurement task, not up front. → ADR 0014.
6. **Rollback target moves from the TypeScript stack to image tags** (`dailybrief-rs:r0`, then `:m2`), which is what `SPEC.md` §9 always intended once a previous Rust image existed. The TypeScript container is removed after M2 ships. → ADR 0015.
7. **`fatal` semantics**: a fourth `publish_digest` after `fatal: true` is refused with the same violation text; the runner still classifies the run by the `result` line (unchanged). Chosen because `SPEC.md` §3 says three rejections end the run as failed.

## 13. Open questions

1. **Should the digest page (success state) carry a one-line run summary** ("78 turns · 8:20 · attempt 1") linking to the run page, or only the failed state? Default: a link only, to keep the 15 KiB cap and the reading surface quiet.
2. **Prune schedule time**: right after the morning run (about 06:45) or at a quiet hour (03:00)? Default: 07:00 local, after the run window, so a slow run is never pruned mid-flight.
3. **Keep `readability`?** Decided by the measurement task: if the fallback rescued fewer than 2 % of articles over the last 60 days, drop it.
